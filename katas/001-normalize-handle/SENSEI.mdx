# SENSEI — 001 Normalize a Handle

## Briefing

### Goal

Build a small pure function that converts a display name into a stable handle.

### Tasks

Trim outer whitespace, lowercase letters, and collapse each internal whitespace
run into one hyphen. Empty or whitespace-only input remains empty.

## Prerequisites

Basic TypeScript functions and string methods. Regular-expression syntax is
explicitly taught here; never assume the learner already knows it.

<Stage id="whitespace-class">
  <Objective>Understand that `\s` denotes whitespace in a regular expression.</Objective>

  <Present id="whitespace-class">
    ### Matching whitespace

    A regular expression describes text to find. MDN's
    [character-class escape reference](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Regular_expressions/Character_class_escape)
    explains the predefined class for whitespace, including spaces, tabs, and
    newlines.

    Pay attention to MDN's distinction between a regex literal and a pattern passed
    through the `RegExp` constructor: the latter is also a JavaScript string, so
    JavaScript string escaping happens before the regex engine sees it.

    Example: applying the whitespace class once to `"red   blue"` identifies
    only the first space. Let the learner predict that result before continuing.
  </Present>

  <Probe>
    After presenting `whitespace-class`, ask the learner to explain why `"\s"`
    in the constructor does not preserve the regex backslash but `"\\s"` does.
  </Probe>
</Stage>

<Stage id="whitespace-runs">
  <Objective>Understand how `+` groups adjacent whitespace into one match.</Objective>

  <Present id="whitespace-runs">
    ### Matching a complete run

    Read MDN's [quantifier guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions/Quantifiers)
    and compare “one or more” with “zero or more.” A quantifier applies to the item
    immediately before it.

    A zero-length match can occur between letters, which explains why the wrong
    quantifier may insert replacement characters where no input character exists.

    Example: in `"red   blue"`, compare matching one space at a time with
    treating the three adjacent spaces as one match.
  </Present>

  <Probe>
    After presenting `whitespace-runs`, ask why `+` produces one hyphen for three
    adjacent spaces while `*` can also match between letters.
  </Probe>
</Stage>

<Stage id="global-replacement">
  <Objective>Understand that `g` continues matching throughout the input.</Objective>

  <Present id="global-replacement">
    ### Replacing every run

    MDN's [regular-expression flags reference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/global)
    explains the flag that continues searching after the first match.

    Keep the responsibilities separate while you reason:

    - the pattern selects what counts as a match;
    - a quantifier controls the size of one match;
    - a flag controls whether searching continues.

    Example: use `"cat, dog, cat"` to contrast replacing only the first `cat`
    with continuing the search through the whole string.
  </Present>

  <Probe>
    After presenting `global-replacement`, ask the learner to predict how the
    result differs with and without `g` for a three-word name.
  </Probe>
</Stage>

## Test Map

| Test | Concept | Verifies |
|------|---------|----------|
| trims and lowercases | transformation pipeline | outer whitespace and casing |
| collapses mixed whitespace | `\s`, `+`, and `g` | a mixed run becomes one separator |
| leaves canonical input unchanged | idempotence | a normalized value remains stable |
| handles whitespace-only input | boundary case | no accidental hyphen is produced |

## Common misconceptions

- A literal `s` matches the letter s, not whitespace. Present `whitespace-class`.
- `\s` without `+` matches each whitespace character separately. Present `whitespace-runs`.
- A pattern without `g` replaces only its first match. Present `global-replacement`.
- `*` permits zero characters. Contrast it with `+`; do not merely ask for the name.

## On Completion

### Insight

A pure normalization boundary makes every later domain operation consume one
stable representation.

### Bridge

The next kata uses that canonical value inside an explicit success-or-failure result.

### Review topics

When the learner chooses Review, always clarify method chaining versus currying,
then choose two connected topics below. Ground them in the learner's actual
expression rather than reciting every item. Another Review can explore a
different set.

- The sequence is method chaining and a transformation pipeline, not currying.
  Currying converts a multi-argument function into nested one-argument functions.
- Ordering is observable: trimming before replacement prevents boundary
  whitespace from becoming separators.
- `toLowerCase()` is appropriate for a stable machine identifier;
  `toLocaleLowerCase()` intentionally varies for locale-sensitive human text.
  Mention Unicode normalization as a separate production concern, not a hidden
  requirement of this kata.
- The normalizer is idempotent: normalizing an already canonical value should
  leave it unchanged.
- `\s`, `+`, and `g` have separate responsibilities: character class, match
  size, and search continuation.
